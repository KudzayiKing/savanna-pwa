### The bug (caused by my own earlier change)

Converting `vite.config.ts` to the function form `defineConfig(({ mode }) => …)`
made its **default export a function**. `server/_core/vite.ts` did
`createViteServer({ ...viteConfig })` — spreading a function yields `{}`, so
`root`, `publicDir`, `resolve.alias` and `envDir` were silently dropped in dev.

Symptoms (all quiet, nothing in the logs):
- `client/public` not served → `/manifest.webmanifest`, `/service-worker.js`,
  `/icons/*.svg` all fell through to the SPA index.html
- every `@/…` and `@shared/…` import failed to resolve

Fix: added `resolveViteConfig()` which awaits the function form when the export
is callable, and merged `server` options (`{...baseConfig.server, ...serverOptions}`)
instead of replacing them — replacing also silently disabled `fs.strict` and
`fs.deny`. Guarded by a new `server/vite-config.test.ts`.

**Lesson:** when `vite.config.ts` is the function form, anything importing it
directly (rather than letting the Vite CLI resolve it) must call it first. A
spread of a function fails silently.

## Light-mode colour fixes on /shops, /learn, /orders (per user report)

User screenshot of /shops showed the search "Search shops or products"
blending into the white page, the inactive filter tabs ("Products", "Shops")
too tinted, and complained "there its green" on /learn and /orders with
"we are not supposed to have any green logos in the app". Could read the
screenshot this turn (vision worked).

### Cascade (light mode) — what was actually rendering

The "semantic palette bridge" in `client/src/index.css` (around line 235–320)
remaps legacy hex utilities to the Savanna palette. Key bindings:
- `bg-white` and `bg-[#fffaf0]` etc. → `#FFFFFF`
- `.savanna-discovery-card` → `#F6F5F5` (so card = soft grey)
- `.savanna-route-search` on shops/learn — *intended* `#F6F5F5`, but the
  `bg-white` utility + line 1212 (0,5,0) override forced it to `#FFFFFF`
- `text-[#24482f]` / `text-[#31583a]` → **`#2F6B4F` (the green the user saw)**
- `bg-[#24482f]` → `#16231D` (very dark)
- `bg-[#f7e5bd]` → `#FFF4D8` (icon tile)
- `text-[#9a6410]` → `#A87820` (icon)

So the search was white-on-white, the inactive tabs were `#FAFBF8`
(`--elevated-surface`) against a `#FFFFFF` page, and /orders had literal
green icons (`Store`, `PackageCheck`) plus green amount text.

### Fix

1. **`OrdersPage.tsx`** — full rewrite as clean multi-line. Replaced every
   green/greenish token with the gold/brown family used on /shops and /learn:
   - amounts `text-[#24482f]` → `text-[#7b4a0d]`
   - spinners/merch outline btn `text-[#31583a]` → `text-[#9a6410]`
   - `PackageCheck text-[#5c815d]` → `text-[#9a6410]`
   - CTA fills `bg-[#24482f] hover:bg-[#1b3b25]` → `bg-[#5d3a0c] hover:bg-[#412607]`
   - icon tiles `bg-[#e8dfc9] / bg-[#dfe8d9]` → `bg-[#f7e5bd]`
   - borders → `border-[#eadfca]` / `border-[#ead2a4]`
   - empty-state `bg-[#f5f7f3]` → `bg-[#fffaf0]`
   - shadows `rgba(39,54,37,…)` → `rgba(94,58,11,…)`
   - StatusPill fallback → `bg-[#FFFDF8] text-[#8a765d]`
   Preserved every StatusPill string the test asserts on.

2. **`ShopsPage.tsx`** — search border `border-[#d5ddd0]` → `border-[#eadfca]`;
   placeholder `placeholder:text-[#92a08e]` → `placeholder:text-[#aa967b]`;
   product-card shadow `rgba(39,54,37,0.03)` → `rgba(94,58,11,0.03)`. (Shop
   card shadow already used brown.)

3. **`client/src/index.css`** — appended a route-scoped light-mode cascade at
   the end of the file:
   - `.savanna-route-search` on shops/learn/orders → `#F6F5F5` (card colour)
     + `input` transparent so the label fill shows through
   - inactive `.savanna-discovery-tabs button` → `transparent` (page bg)
     with muted `#DDE3DC` border
   - `[class~="bg-[#f7e5bd]"]` / `[class~="text-[#9a6410]"]` on the three
     routes → soft-gold tile + deep-gold icon
   - /orders safety net: any `[class~="text-[#24482f] / text-[#31583a] /
     text-[#5c815d]"]` → `#A87820`; `[class~="bg-[#dfe8d9] / bg-[#e8dfc9]"]`
     → `#FFF4D8`; `[class~="bg-[#f5f7f3]"]` → `#FFFFFF`; legacy borders →
     `#DDE3DC`. So even a future regression can't paint /orders green.
   - Scoped to the three routes, so /messages and the bottom-nav stay untouched.

### Lesson

`bg-white` + a route-scoped bridge rule can silently flip a "soft fill" to
"white" when the element's other class tokens get matched by `[class~="bg-white"]`
with higher specificity than the design rule. The fix is either drop `bg-white`
or add a final-cascade override; chose the override so /messages' cream pill
(also named `.savanna-desktop-chat-search`) is unaffected by the same class.

## Follow-up: card icons + text → brand gold #D9A441 (light mode)

User follow-up: "in the cards on /shops /learn icons and text are #a87820 they
should be #d9a441 fix them in lightmode".

The global palette bridge maps `text-[#9a6410]` and `text-[#7b4a0d]` to the
**deep** gold `#A87820` (index.css line ~285). The route CTA buttons were
already `#D9A441`, so cards and buttons disagreed by one gold step.

Extended the route-scoped light-mode block at the end of index.css:

```css
:root:not(.dark) .savanna-app :is(.savanna-route-shops, .savanna-route-learn, .savanna-route-orders)
  :is([class~="text-[#9a6410]"], [class~="text-[#7b4a0d]"], [class~="text-[#a4660d]"], [class~="text-[#775b31]"]) {
  color: #D9A441 !important;
}

:root:not(.dark) .savanna-app :is(.savanna-route-shops, .savanna-route-learn, .savanna-route-orders)
  [class~="bg-[#f7e5bd]"] svg {
  color: #D9A441 !important;
}
```

Also bumped the /orders green safety net from `#A87820` → `#D9A441` so all three
routes share one gold.

**Deliberate exclusions (do not "fix" these):**
- The Learn course-cover `BookOpen` is `text-white/70` on a gold gradient. Scoped
  the icon rule to `[class~="bg-[#f7e5bd]"] svg` rather than a blanket
  `.savanna-discovery-card svg` so it stays white — a blanket rule would have
  made it gold-on-gold/invisible.
- `/orders` status pills use literal `text-[#A87820]` for "Awaiting payment" /
  "Preparing" vs `#D9A441` for "Paid"/"Completed". Left alone: forcing them to
  one gold would destroy the status semantics.

**Contrast caveat (raised with the user, not blocked on):** `#D9A441` on white is
~2.25:1 and on the `#FFF4D8` icon tile ~2.06:1 — below WCAG AA (4.5:1 text /
3:1 UI). The previous `#A87820` was ~3.57:1 on the tile. This is a brand-design
call; if accessibility ever becomes a gate, the tile needs a darker gold.
