## Splash-screen sound waves on new Savanna logo (REBUILT — v2)

**First attempt was rejected by the user** and fully reverted: I had invented
four *new* arcs on top of the logo, centred at viewBox (955, 615) with radii
95/145/200/260. They overflowed the chat bubble, and the user pointed out the
logo **already has** sound waves — there are three, not two. Lesson: don't add
decoration over artwork; animate what's already there.

### What `savanna_new_logo.svg` actually is
A 1251x1235 raster PNG wrapped in SVG (`<image id="img1">` in `<defs>` +
`<use y="19">`), viewBox `0 0 1254 1254`. **PNG(x,y) -> SVG(x, y+19).**
Artwork: gold chat bubble (circle ~centre PNG(619,598) r~444 + tail
bottom-left) with a dark megaphone and **three dark arcs** on the right.
Gold is essentially flat: `#DDAB2B` +/-2 per channel across the whole bubble
(measured), which is what makes the trick below invisible.

### The approach that worked (no raster edit needed)
1. Measure the three real arcs: connected components on dark pixels (6
   components: 3 megaphone parts + 3 rings; the rings are the 3 smallest).
2. Fit each arc (bbox algebra: `cy=(ymin+ymax)/2`, stroke = run width at
   `y=cy`, then solve for cx/r/theta) and refine by IoU against the real
   pixels. Final IoU 0.986 / 0.978 / 0.977.
3. In the SVG, draw the same three arcs **twice**:
   - a gold "cover" pass (`stroke:#DDAB2C`, width = stroke + 8) that paints
     over the baked-in raster arcs — invisible because the gold is flat;
   - the real arcs (`stroke:#0E0E10`, exact geometry) as animatable paths.
   Result: identical to the original when visible, and the rings are true
   vectors that cannot spill outside the bubble. Zero pixels changed outside
   the arc bands (verified).

Arc params (PNG space; SVG = y+19), `M cx+r*cos0 cy-r*sin0 A r r 0 0 1 ... end`:
| ring | cx | cy | r | stroke | theta |
|---|---|---|---|---|---|
| inner | 761.45 | 574.00 | 59.55 | 32.50 | 49.97 |
| mid   | 747.47 | 572.00 | 136.03 | 38.00 | 45.75 |
| outer | 730.80 | 570.00 | 223.20 | 38.50 | 44.19 |

Animation: 2.6s loop, per-ring `@keyframes` (a single delayed keyframe set
can't reverse direction halfway). Appear inner->outer, vanish outer->inner:
- inner 0/7%/77%/84%  mid 8/15%/65%/72%  outer 17/24%/54%/61%
`prefers-reduced-motion` -> `animation:none; opacity:1` (static logo).

### Verified by rendering, not by eye
Headless Chrome + **frozen frames** (`animation-play-state: paused` with a
negative `animation-delay`) is the trick for photographing a CSS animation at
a chosen phase — `--virtual-time-budget` does NOT advance CSS animations.
Measured ink per ring per frame confirmed the order; the all-visible frame
differs from the original raster-only render by 0.23% of pixels, all on the
arc edges (antialiasing), 0 elsewhere.

### Rail logo animates on hover only (follow-up)
User then asked for the web sidebar logo to animate **only while hovered**.
Because the animation lives inside the SVG, an `<img>` gives no way to
pause it — CSS can't reach into an `<img>`-referenced SVG document. So:
- new `client/public/savanna_new_logo_icon.svg`: the same raster
  box-downsampled to 256x253 (56 KB vs 970 KB) with the waves baked in.
  Placed with `<image width="1251" height="1235" x="0" y="19">` in the same
  `0 0 1254 1254` viewBox so the framing is identical.
- `SavannaShell.tsx` rail link is now `group` + two stacked `<img>` layers
  (static visible, animated `opacity-0 group-hover:opacity-100`, 150ms).
  Two layers rather than swapping `src` so there's no decode hitch on first
  hover; the animated file is already fetched for the splash anyway.
- Kept the literal `src="/savanna_new_logo.svg"` in the shell (pinned by
  `pwa.assets.test.ts:1442`) — the static one is the *added* layer.
- SW: added the icon to `SHELL_URLS` and bumped v27 -> v28 (also in
  `main.tsx` `?v=28` + the two pinned test assertions).

General rule learned: **an `<img>` cannot have its internal SVG animation
controlled from outside** — you either split files or inline the SVG.
